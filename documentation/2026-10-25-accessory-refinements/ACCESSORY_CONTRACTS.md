# Accessory refinement contracts

Snapshot: codex/accessory-refinements, 2026-10-25; implementation 5a6e1ecc.

- Static gauge installation/removal is a server-thread transaction immediately after queue acceptance, exact stack/hand, identity, revision, permission, reach and collision validation. Accepted crash-surviving pending transactions retain the validated replay path. No solver runs on an interaction. Gauge inventory transfer/static BE metadata arrive immediately; cached readings and hydraulic valve/filter changes keep the engine schedule.
- InstrumentService clears/finishes the immediate operation once; AccessoryStore retains instance/revision tombstones, configured refunds and one accessory per pipe. Pipe valve removal uses latest projected registration so diameter edits survive and old committed controls cannot restore a removed fitting. FluidDeviceBlockEntity refreshes static model data even if an isolated host's bore/faces did not change.
- Horizontal pipe taps use an upward boss and bottom-entry dial stem; vertical runs use a lateral tap/elbow with an upright dial. Dials face the player at installation and may overhang the block. Direct vanilla pipe hits select a mount, without invisible-socket aiming. Supported straight/end/isolated sections expose four horizontal dial headings; the process tap is lateral/up regardless of heading. Corners/junctions and occupied slots reject installation. No pipe ghost or outline is rendered; restrained reservoir previews remain.
- Pressure and temperature measurements retain the approved hydraulic datum and accepted bulk temperature. Connectors imply no new process storage, pressure head correction or thermal model. Thermometer stem includes a thin immersed thermowell-style probe (wall plus two-thirds bore, capped at0.12 m); pressure uses a hex process boss. Research: WIKA Pressure & Temperature Handbook and FAQ (links in plan).
- Closed 0.34 m opaque housing: rear cap, outside wall, bezel annulus, inner bezel wall and dial form a watertight envelope. Ghosts use their own translucent layer. Face/ticks/labels/needle depths are 0.045/0.047/0.050/0.057 m, bezel 0.068 m. Five larger numerals, heavier ticks/needle and lower unit/reference label avoid overlaps. Cached connectors and housing are shared. Aiming shows one line: numeric measurement with units/reference, or unavailable; no title, range, sample age or status lines.
- FluidDeviceScreen reading rows use a shared 24 px stride, value baseline +10 px, and matching hover/scroll extents. Units and cached process publications are unchanged.
- icheme:inline_filter is now a stack-64 application item (creative/commands, no recipe). Either hand installs on a bare straight/end/isolated pipe, aligned and locked to its run axis; consume one in survival. No block or hydraulic identity is replaced. It excludes every other pipe accessory, reapplication consumes nothing, ordinary break/wrench returns one fitting. Native command-only filter block registration remains for authoring, not item placement or migration.
- Physical Device.inlineFilter is pipe-only, passive and incompatible with cutoff/pressure control. hydraulicKind FILTER routes through existing topology, cake, resistance, solids/energy recovery and existing filter GUI. Removal queues the ordinary host plus one world recovery for captured solids/energy, using the same ledger recovery as filter breaking. Item/model removal is immediate; cake/hydraulic application remains scheduled. Shared fitting recovery prevents duplicate accessory drops.
- Checkpoint 19 / unit format 12 encode the validated filter flag in active and pending registrations. Accessory storage 1 gains FILTER type; fluid-14 and instruments-1 payloads are unchanged. No migration/legacy normalization; fresh-world validation only. Incompatible worlds follow the existing owner-approved fluid reset policy.
