# Fluid GUI contracts

Implementation `f44930f5`, 2026-10-24, branch `codex/fluid-gui-consistency`.

- Every `FluidDeviceScreen` uses a common readings-row plan, scrollable left rail, status summary/full status, adaptive tabs and footer. The footer order is Close, Apply where editable, component/flow basis, temperature, pressure, flow-time basis. Ratio basis is beside its phase block.
- Session defaults: Celsius, kPa, /s, component/flow Mole, phase Volume. Choices survive moving between equipment screens during the client session. Ratio choice is independent of composition input and flow basis.
- `DisplayUnit.display/si` converts physical SI values. `NumericDraft` retains exact SI behind concise text; converting units reads edited text once. All drafts affected by a unit switch validate before replacement. Invalid text remains available to fix.
- `PressureUnit` cycles Pa/kPa/bar/MPa and retains the existing 0.1 Pa display resolution. It covers absolute pressures, signed changes, pressure-rise inputs, outlet head and path gradient. Apply sends Pa/K/m3 per second regardless of display unit; server validation/revisions are unchanged.
- `PhaseRatioBasis` cycles Volume/Mole/Mass. Fluids use published phase volumes/moles and molecular weights in kg/mol. Volume/mass include all solids; molar solids count crystals using their conserved component and exclude custom solids lacking molecular identity, with visible notice and tooltip.
- Generator ratios describe published configured feed, reservoir ratios stored contents, transport ratios accepted passing material. Zero transported material gives no ratio. Mover tables use discharge transport, not resident suction-buffer stock. Filters keep their captured-solids table while the ratio describes their passing stream.
- Throughput is kg or kmol per selected second/hour. Pipe/filter/valve/mover/void rates use accepted transfer divided by the published interval; reservoir net outward flow sums published outlets. Mover setpoint remains suction m3 per second/hour. Pipe bulk speed keeps its existing recent-five-second window.
- Reservoir top pressure is state pressure. Bottom is top + g * condensed mass * levelHeight / capacity, exactly the existing bottom/overflow head expression. Condensed mass includes both liquids and solids. Empty tanks publish capacity but no pressure pair.
- Live `FluidView.Tank` adds positive finite capacity and paired nullable top/bottom pressures (positive finite and bottom >= top). Menu validation requires a reservoir, state/pressure availability agreement and matching capacity. Tank level uses the published capacity and is zero without state.
- `FluidNetwork.PROTOCOL` is `fluid-14`; static/live payload split and size limits remain. No compatibility path. Checkpoint 18 and storage-unit 11 do not change: these are ephemeral presentation fields.
- `PipePresentation.actuatorMappings` selects non-passive graph pipes whose first node is the mover identity. `FluidWorldAuthority.view` uses those discharge mappings for mover history/contents while retaining pipe-hosted controller mappings and existing pressure/status logic.
- All arithmetic consumes existing snapshots. Menu opening replays cached data and subscribes; closing unsubscribes. No process solve, pending input application or time advancement occurs on opening, unit switching or basis switching. Publications remain requested engine buckets.
